# S0-06 — ADR-006 Security and DPDP

What changed: Added `docs/adr/ADR-006-security-and-dpdp.md`. Shared KMS key (per environment) for Phase 1 with strict tenant-context/RBAC access controls; field-level envelope encryption for PAN/bank/salary via a `FieldEncryptor` seam; never store full Aadhaar (masked/last-4 or verification token only); blind-index (keyed HMAC) + last-four for searchable encrypted data; DPDP consent/access/erasure/breach processes with erasure reconciled against statutory retention.

Risks: shared key means tenant key isolation relies on the app layer (seam preserved to move to per-tenant keys later); field encryption breaks native SQL filter/sort on those columns (must use blind-index/last-4); DPDP erasure-vs-retention conflict needs a documented per-category policy.

How to verify: read the ADR; confirm shared-KMS, blind-index, and Aadhaar stance match your decisions. Open questions need compliance input: exact sensitive-field classification, erasure-vs-retention matrix, whether Aadhaar verification is in Phase-1 scope.
