# B1-15 — Frontend: platform services demo→live for the B1 surface

Owner: Frontend. Branch: `agent/B1-15` (worktree `../hrms-saas-worktrees/B1-15`).
Scope anchor: `docs/B1_PLAN.md` §B1-15, ADR-007, ADR-008, `docs/ui/PLATFORM_API_SPEC.md`,
`openapi.yaml` (read-only source of truth). Human decision **E-1: FOUNDATIONS ONLY**.

## What changed (frontend only)

Switched the platform console's **in-scope read services** from demo→live against the
contract where the B1 endpoints actually exist in `openapi.yaml`, reconciled platform role
labels to the fixed `PlatformRole` enum, reconciled the `impersonate`→`access` permission,
and added tenant `inactive` status handling. No tenant-application module was switched; no
backend/contract/ADR file was touched.

Files:
- `frontend/src/lib/platformRoles.ts` **(new)** — single source of truth for the fixed
  `PlatformRole` enum, the `platform.*` permission catalog (with `platform.tenant.access`),
  the role→permission map (per PLATFORM_API_SPEC), the demo-slug→enum reconciliation, and
  human role labels.
- `frontend/src/lib/config.ts` — added `platformApiBaseUrl` (base-domain `/platform` API,
  NOT tenant-scoped — ADR-007).
- `frontend/src/lib/api/client.ts` — added `apiFetchPlatform` (platform-plane fetch on the
  base domain; shares the request core with the tenant `apiFetch`). The tenant client stays
  tenant-subdomain-scoped; the two never cross.
- `frontend/src/services/platform.ts` — in-scope reads now call live endpoints in live mode;
  demo in demo mode.
- `frontend/src/services/platformAuth.ts` — demo identity now speaks the fixed enum +
  reconciled permissions; stays demo-backed (login/MFA not wired live — see below).
- `frontend/src/types/platform.ts` — `TenantStatus` gained `inactive`; `PlatformUser.platform_role`
  is now the fixed `PlatformRole` enum; added the `PlatformRole` type.
- `frontend/src/lib/status.ts` — explicit tone/label for the full ADR-008 lifecycle set
  (`provisioning|trial|active|suspended|inactive`); `inactive` renders as neutral "Inactive".
- `frontend/src/lib/demo/platform.ts` — one tenant is now `inactive`; demo users use the fixed
  enum (billing-admin→Auditor demo seat); audit "impersonated" entry relabelled to
  "access_session.started"; summary status split includes Inactive.
- `frontend/src/app/(platform)/platform/tenants/page.tsx` — `inactive` added to the status
  filter; status badge renders directly (dropped the `provisioning→in_progress` workaround);
  "View tenant" guard reconciled to `platform.tenant.access`.
- `frontend/src/app/(platform)/platform/tenants/[id]/page.tsx` — same badge fix + access guard;
  lifecycle actions respect ADR-008 (`inactive` is terminal → no activate/suspend action,

- `frontend/src/app/(platform)/platform/users/page.tsx` — renders the human role label.
- `frontend/src/components/providers/PlatformSessionProvider.tsx` + `components/shell/PlatformShell.tsx`

  model (ADR-007 §6); stays demo-only; read-only banner wiring preserved for B3.
- `frontend/src/services/platform.test.ts` — expanded (role-label mapping, impersonate→access,
  inactive handling); preserved the platform/tenant permission-separation assertion.

## Wired LIVE vs stayed DEMO

| Service function | Contract endpoint (openapi.yaml) | Status |
|---|---|---|
| `getPlatformSummary` | `GET /platform/summary` | **LIVE** (live mode) |
| `listTenants` | `GET /platform/tenants` (q/status/plan/page) | **LIVE** |
| `getTenant` | `GET /platform/tenants/{id}` | **LIVE** |
| `listTenantOnboarding` | `GET /platform/onboarding` | **LIVE** |
| `listPlatformUsers` | `GET /platform/users` | **LIVE** |
| `listPlatformAudit` | `GET /platform/audit` (page) | **LIVE** |
| `listPlatformPlans` | `GET /platform/plans` | **LIVE** |
| `listSecurityAlerts` | *(none — no `/platform/security*` in contract)* | **DEMO (flagged)** |
| platform login / MFA / `me` (`platformAuth.ts`) | `/platform/auth/*` exist, but B1=foundations | **DEMO (flagged, "FE ahead of contract")** |
| read-only access-session ("View tenant") | `POST/DELETE /platform/tenants/{id}/access-sessions` | **DEMO-only** (B1 built state model, no live minting — B3/SEC-3) |

Why login/MFA/access-session stay demo: B1_PLAN.md §0 (E-1) and PLATFORM_API_SPEC "Frontend
reconciliation" put full login/MFA UX into B2 and live access-session issuance into B3
(SEC-2/SEC-3). The brief explicitly says do NOT wire login/MFA/access-session to live. The
backend built only the FOUNDATIONS (guard, token audience, access-session state model with no
live minting), so the FE stays on demo for those and is flagged. `NEXT_PUBLIC_DATA_MODE=demo`
remains the default build mode, so the console is fully navigable with no backend.

Only the data-mode-switched READ functions change behavior under `NEXT_PUBLIC_DATA_MODE=live`;
the UI is unchanged (DEMO_MODE_ARCHITECTURE). Live calls go to the base-domain `/platform` API
via `apiFetchPlatform`, never a tenant subdomain.

## Role-label mapping decision (ADR-007 §4 / B1-03)

Fixed enum (the ONLY platform roles): `PLATFORM_SUPER_ADMIN | PLATFORM_SUPPORT |
PLATFORM_OPERATIONS | PLATFORM_AUDITOR`. The FE demo previously used slugs
`super-admin / platform-operator / support-engineer / billing-admin`.

Reconciliation (FE label mapping only — no backend role invented, no contract change):
- `super-admin` → `PLATFORM_SUPER_ADMIN`
- `platform-operator` → `PLATFORM_OPERATIONS`
- `support-engineer` → `PLATFORM_SUPPORT`
- **`billing-admin` → `PLATFORM_OPERATIONS`.** The demo "billing-admin" has NO fixed enum
  value. Per PLATFORM_API_SPEC "Frontend reconciliation", it folds into `PLATFORM_OPERATIONS`,
  which carries `platform.billing.manage`. No standalone platform "billing" role exists in
  Phase 1.
- **`PLATFORM_AUDITOR` added.** It had no demo slug; it is now a first-class, read-only role
  (dashboard/tenant view, audit view, settings view — no manage/create/suspend/activate), and
  it appears in the preview switcher. The old "Billing Admin" demo seat is now an Auditor seat.

Role→permission map follows PLATFORM_API_SPEC exactly (`permissionsForRole`).

## Impersonate → access reconciliation (ADR-007 §6)

The demo permission `platform.tenant.impersonate` is removed from the FE catalog and replaced
by the fixed catalog value **`platform.tenant.access`** (ADR-007 §6 names it a read-only
"access-session", not impersonate). All UI guards that previously checked
`platform.tenant.impersonate` (tenant list + detail "View tenant") now check
`platform.tenant.access`. The demo "View tenant" UX remains **demo-only** and clearly labelled
(impersonation banner / toast say "demo"); it does NOT become a live access-session in B1 — the
production equivalent (read-only, reason-required, 15-min, double-audited token) is B3. The
read-only access-banner wiring is preserved for that switch. The demo audit entry that read
"tenant.impersonated / support session" now reads "tenant.access_session.started / read-only
access session" (category `access`, matching the contract).

## `inactive` handling (ADR-008)

- `TenantStatus` now includes `inactive` (full set `provisioning|trial|active|suspended|inactive`,
  mirroring the contract `TenantStatus`).
- `status.ts` maps the whole lifecycle set to explicit tone+label; `inactive` → neutral
  "Inactive" (never color-only — paired with a label via `StatusBadge`).
- Tenant list: `inactive` added to the status filter; badge renders directly.
- Tenant detail: `inactive` is treated as **terminal** per ADR-008 (no transition back to
  live) — no activate/suspend action is offered; a neutral "Offboarded — terminal" pill shows
  instead. `provisioning` now exposes Activate.
- Demo seed includes one `inactive` tenant (dormant: 0 employees, MRR 0, health down) and the
  dashboard status split counts it.

## Session separation (preserved)

Platform and tenant sessions remain in SEPARATE localStorage keys (`lib/session.ts`
unchanged in substance). The platform fetch uses the platform base URL + platform token path;
the tenant fetch stays tenant-subdomain-scoped. The FE never holds a tenant+platform session
granting cross privileges. The permission-separation unit test (platform identity contains
only `platform.*`, never tenant perms) is preserved.

## No OpenAPI / ADR drift

`openapi.yaml`, `docs/adr/**`, `docs/reviews/**`, and `backend/**` were READ only and NOT
modified. `git status` on `agent/B1-15` shows changes under `frontend/**` plus this note only.
No endpoint was invented: every live call targets a path present under `/platform` in the
contract; services with no contract endpoint stay demo and are flagged above.

## How to verify

```
cd frontend
npm install
npm run typecheck   # passes (strict)
npm test            # 34 pass (was 22; +12 platform tests for role mapping, impersonate→access, inactive)
npm run lint        # no warnings or errors
npm run build       # succeeds
```

Actual results captured this run: typecheck clean; `34 passed (6 files)`; lint "No ESLint
warnings or errors"; build succeeded (platform routes present).

Manual (demo mode, default): `npm run dev` → `/login` → "Platform operator sign in" →
`/platform/tenants`: see the **Inactive** filter option and an inactive tenant badge; open the
inactive tenant → it shows "Offboarded — terminal" with no activate/suspend. `/platform/users`
shows roles Super Admin / Operations / Support / Auditor. The "View as" switcher lists all four
fixed roles incl. Auditor; narrower roles hide actions they lack.

Live mode (when the backend endpoints are available): set `NEXT_PUBLIC_DATA_MODE=live` and
`NEXT_PUBLIC_PLATFORM_API_BASE_URL=https://app.example.com/api/v1/platform`; the in-scope reads
call the live contract. Login/MFA/access-session stay demo and are flagged.

## Risks / follow-ups

- Login/MFA (`/platform/auth/*`) and the read-only access-session go live in B2/B3 behind
  SEC-2/SEC-3; the FE affordances are intentionally ahead of the live wiring and flagged.
- `listSecurityAlerts` has no contract endpoint; either add one via the planner or treat it as
  a derived view of `/platform/summary` + `/platform/audit` at the B-x live switch.
- `inactive` retention period is a legal/compliance policy (ADR-007/008 open question); no FE
  action beyond rendering the terminal state.
