## How the branch was assembled
Dependencies for B1-13 are B1-01 (`tenants` table + `Tenant` model), B1-04
(`TenantLifecycle` + `TenantLifecycleException` + 409 mapping) and B1-05
(`ResolveTenant` host resolution + reserved labels + status gating).

Commit lineage (checked with `git log`):
- `agent/B1-01` builds on `agent/B1-00` (linear).
- `agent/B1-04` builds on `agent/B1-01` (so B1-04 already contains B1-00+B1-01+B1-04).
- `agent/B1-05` branches directly off `agent/B1-00` (does **not** contain B1-01/B1-04).

Therefore:
```
git worktree add -b agent/B1-13 C:/xampp/htdocs/hrms-saas-worktrees/B1-13 agent/B1-04
cd C:/xampp/htdocs/hrms-saas-worktrees/B1-13
git merge --no-ff agent/B1-05 -m "B1-13: assemble lifecycle test branch (merge B1-05 ...)"
```
The merge was **clean** (ort strategy, no conflicts): B1-05 adds only new files
(`app/Tenancy/*`, `ResolveTenant.php`, `TenancyServiceProvider.php`,
`config/tenancy.php`, its own tests, `docs/notes/B1-05.md`).

B1-09 was **not** needed: `TenantLifecycle` emits audit via the
`PlatformAuditLogStore` seam, bound in `AppServiceProvider` to
`InMemoryPlatformAuditLogStore` (B1-04's temporary store). That in-memory store
is sufficient to assert "exactly one audit event per transition", so B1-04's
store suffices per the task's own guidance.

## Full transition-matrix coverage (ADR-008)

Statuses: `provisioning, trial, active, suspended, inactive` → **25 ordered pairs**.

LEGAL (10) — all asserted applied + persisted (I1):

| from \ to | provisioning | trial | active | suspended | inactive |
|---|---|---|---|---|---|
| **provisioning** | ✗ | ✓ | ✓ | ✗ | ✗ |
| **trial** | ✗ | ✗(self) | ✓ | ✓ | ✓ |
| **active** | ✗ | ✗ | ✗(self) | ✓ | ✓ |
| **suspended** | ✗ | ✓ | ✓ | ✗(self) | ✓ |
| **inactive** | ✗ | ✗ | ✗ | ✗ | ✗(terminal) |

ILLEGAL (15) — all asserted → 409 `Error`, unchanged, not persisted, no audit
(I2/I4). This includes all 5 self-transitions and all 4 out-of-`inactive`
pairs (the latter also asserted to carry the dedicated `CODE_TERMINAL_STATE`
via I3). 10 + 15 = 25 = full matrix.

## Contract `Error` shape (verified, no drift)
`openapi.yaml` `#/components/schemas/Error` =
`{ error: { code (required), message (required), request_id? } }`.
The suite asserts exactly this: required `code`+`message` strings, optional
`request_id` (echoed from `X-Request-Id`), and that the body contains **only**
the `error` envelope. `TenantLifecycleException::render()` + the
`bootstrap/app.php` renderer produce this shape at HTTP 409.

## Spec note (not a bug) — reserved-label "422" vs "no tenant"
`B1_PLAN.md` B1-13 acceptance lists "reserved labels rejected (`422`)". In B1
there is **no onboarding/create/validation endpoint yet** (those are B2/B3), so
`422` is not reachable in this branch. The reachable B1 guarantee — and the one
in the task **objective** text ("a reserved label ... cannot be a tenant and
resolves to no tenant") — is enforced by `ResolveTenant`: a reserved label
short-circuits to **no tenant** (HTTP 200, `has_tenant:false`) *before any
lookup*, even if a stray matching row exists (I6). The `422` validation on
reserved subdomains belongs to the future create endpoint and should be
re-tested when that lands. Flagged for SEC-1 (B1-14) and the planner; no ADR or
contract change proposed.

## Risks / notes
- `pending`-at-DB-enum: on sqlite the migration `enum` degrades to a string, so
  a `pending` write is not rejected at the DB layer *in tests*. The guarantee
  that `pending` never exists is enforced at the model/service/config layer
  (I8). On MySQL the native `ENUM` adds a DB-level backstop. Documented in
  `test_pending_is_absent_from_the_persisted_enum`.
- The suite registers throwaway routes (`/__b1_13__/...`) in `setUp()` to drive
  the real service + real resolver over HTTP; these are test-only and never
  touch product routes.
- ADR/contract: unchanged. `git diff` on `openapi.yaml` and `docs/adr` is empty.
