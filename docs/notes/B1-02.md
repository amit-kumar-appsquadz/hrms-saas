# B1-02 — Platform identity store (`platform_users`)

Wave 1 (parallel with B1-01/B1-05/B1-08). Branch `agent/B1-02`, cut from `agent/B1-00`.
References: `docs/B1_PLAN.md` §B1-02, ADR-007 §1/§4/§8, steering `hrms-rules.md`.

## What changed

Created the PLATFORM-plane identity store, deliberately separate from the tenant `users` table.

- `backend/database/migrations/2025_01_01_000100_create_platform_users_table.php`
  - Columns: `id, name, email (UNIQUE), password, platform_role, status, mfa_enabled, last_login_at, created_at, updated_at`.
  - `password` column (framework-hashed) satisfies the `password_hash` requirement — named `password` so Laravel's hasher/auth plumbing works unchanged.
  - `platform_role` is an `enum` constrained to the FIXED four values (ADR-007 §4): `PLATFORM_SUPER_ADMIN | PLATFORM_SUPPORT | PLATFORM_OPERATIONS | PLATFORM_AUDITOR`. The enum values are mirrored (not imported) in the migration with a comment — the `PlatformRole` enum CLASS + `PlatformAuthorizer` arrive in **B1-03**. A named `CHECK (chk_platform_users_role)` is added on MySQL/MariaDB/Postgres; Laravel's `enum` adds an inline CHECK on sqlite, so the fixed set is enforced at the storage layer on every supported driver.
  - `status` enum `active|suspended|disabled` (default `active`); `mfa_enabled` boolean **default true** (ADR-007 §3; enforcement is B2).
  - Platform-owned: **NO `tenant_id`**, no tenant-first composite index. Non-tenant helper indexes on `platform_role` and `status`.
  - **No FK to `users`** and no shared/universal user table.
- `backend/app/Models/Platform/PlatformUser.php`
  - `App\Models\Platform\PlatformUser` extends `Authenticatable` (the B1-03 platform guard resolves against it).
  - Explicit `$table = 'platform_users'`. Casts: `password => hashed`, `mfa_enabled => boolean`, `last_login_at => datetime`. `password`/`remember_token` hidden.
  - **Does NOT use `BelongsToTenant`** (trait lands in B1-06; this model must never carry it). `platform_role` stays a plain string until B1-03 swaps in the enum cast — commented in the class.
  - `newFactory()` wires the factory explicitly because the model is in a non-default namespace.
- `backend/database/factories/Platform/PlatformUserFactory.php`
  - Factory + role/status states; defaults `mfa_enabled = true`, role from the fixed four.
- `backend/tests/Feature/Platform/PlatformUserSchemaTest.php`
  - 14 tests / 35 assertions (see output below).

## Scope / boundaries respected

- Did NOT modify any ADR or `openapi.yaml`. No contract drift (this task adds no HTTP endpoints; `platform_users` is a storage/model concern not represented in the OpenAPI schema).
- Did NOT implement the auth guard, `PlatformRole` enum class, or `PlatformAuthorizer` — those are B1-03 by the plan.
- Wrote only within `backend/**` and `docs/notes/**`.

## Risks / notes

- The migration mirrors the four role strings instead of importing the `PlatformRole` enum (which does not exist yet). **B1-03 must keep the enum class in sync** with these strings; the migration comment flags this. Consider having B1-03's enum reference a single shared source if churn appears.
- `platform_role` is a plain string cast today; B1-03 should switch the model to an enum cast once the class exists.
- `status` values (`active|suspended|disabled`) are a reasonable B1 default; if B2 auth needs a different lifecycle, revisit.
- MFA is default-true only; actual enrolment/enforcement is B2 (ADR-007 §3).
