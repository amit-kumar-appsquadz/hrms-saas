### Reconciliations (the two the task flagged)

**Reconciliation #1 — `User::factory()` vs tenant-owned `users` (B1-03 tests × B1-07 migration).**
B1-07 converts `users` to tenant-owned: `tenant_id` NOT NULL, drops global `UNIQUE(email)`, adds
`UNIQUE(tenant_id,email)`. B1-03's tests (`PlatformGuardTest`, `PlatformUserSchemaTest`) use the default
`User::factory()->create()` to represent a generic tenant user; after the merge those inserts failed with
`NOT NULL constraint failed: users.tenant_id` (2 failing tests at the raw merge point).
**Resolution:** supplied a default `tenant_id => 1` in `database/factories/UserFactory.php` with a comment marking it
a B1-12 merge-reconciliation. This is a test-support fixture change only — it changes no product behaviour, and
callers that care about a specific tenant still override `tenant_id`. (The task explicitly authorized
"have the factory supply a `tenant_id`".) Verified: both tests pass; full suite green.

**Reconciliation #2 — two `config/audit.php` files (B1-09 platform block, B1-11 tenant block).**
Merged into a single `config/audit.php` holding BOTH top-level blocks (`platform` → `platform_audit_logs`,
`tenant` → `audit_logs`). The blocks are additive and disjoint (different keys, different fixed collection
names), exactly as B1-11's own in-file reconciliation note anticipated. No key conflict; nothing else changed.
Both fakes still bind under `APP_ENV=testing` (no Mongo/cloud).

Nothing blocked the assembly; all requested branches merged.

## 2. SEC-1 invariant → test mapping

All suites live under `backend/tests/Feature/Tenancy/Sec1/*` and `backend/tests/Feature/Platform/Sec1/*`.
Each file is a named security artifact (overlaps with per-task tests by design, but stands alone as evidence).

| # | Invariant (B1_PLAN §6 / task objective) | SEC-1 test file | Key tests |
|---|---|---|---|
| 1 | Cross-tenant read blocked by the global scope (A ↛ B) | `Tenancy/Sec1/CrossTenantReadIsolationTest.php` | A can't read/find/count B's rows; SQL carries tenant predicate; scope registered; **no tenant ⇒ fail-closed throw** (never all rows); bypass is the only explicit cross path |
| 2 | Token-audience isolation BOTH directions | `Platform/Sec1/TokenAudienceIsolationTest.php` | platform token → tenant endpoint = 401; tenant token → platform endpoint = 401; positive controls both ways; missing token rejected both planes |
| 3 | Separate identity stores (no universal user) | `Platform/Sec1/SeparateIdentityStoresTest.php` | tenant user can't auth via platform guard; platform user can't auth via tenant guard; distinct tables; no shared/universal table or cross-FK; same email = two independent rows |
| 4 | Base/reserved host carries NO tenant (fail-closed, no default) | `Tenancy/Sec1/BaseHostFailClosedTest.php` | real subdomain resolves; base/apex + all 6 reserved labels → no tenant; required-mode → 400 `tenant_required`; **never defaults to a tenant** |
| 5 | `platform.*` ∩ `tenant.*` = ∅ | `Platform/Sec1/PermissionNamespaceDisjointnessTest.php` | catalog intersection empty; every perm in its namespace; no role grants any `tenant.*`; super-admin denied a tenant permission |
| 6 | Access-session state invariants + NO minting path | `Platform/Sec1/AccessSessionStateInvariantsTest.php` | mode fixed `read_only`; TTL clamped ≤15 min (longer clamped, shorter preserved); reason required (empty/whitespace rejected); **no mint/issueToken/token/impersonate method**; platform-owned, no tenant scope |
| 7 | Platform vs tenant audit in SEPARATE collections | `Platform/Sec1/AuditCollectionSeparationTest.php` | fixed names differ; platform event only in `platform_audit_logs`, tenant event only in `audit_logs`; each store refuses the other's collection; tenant audit tenant-scoped + cross-tenant read blocked; both stores append-only (no mutate/delete) |

Determinism / no cloud calls: every test runs on sqlite `:memory:` (phpunit.xml); audit uses the in-memory
collection fakes (ADR-003 "behind an interface"); tokens are HMAC-signed over `APP_KEY`. No MySQL, Mongo, or network.
