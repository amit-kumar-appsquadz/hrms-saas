# B1-09 — Platform audit store (`platform_audit_logs`, separate Mongo collection)

Branch: `agent/B1-09` (worktree `C:/xampp/htdocs/hrms-saas-worktrees/B1-09`), based on `agent/B1-04`
(which carries the audit seam this task fulfils).
Refs: `docs/B1_PLAN.md` §B1-09, ADR-007 §7, ADR-003, `.kiro/steering/hrms-rules.md`.

## What changed

Provides the real, append-only implementation of the `PlatformAuditLogStore` seam that
B1-04 defined, writing to the **separate** MongoDB collection `platform_audit_logs`
(ADR-007 §7), and swaps the temporary in-memory binding over to it.

New files (all under `backend/`):

- `app/Platform/Audit/PlatformAuditCollection.php` — thin append-only seam over the Mongo
  collection. Exposes **only** `name()`, `insertOne()`, `createIndex()`. No update/delete/drop.
  This is the ADR-003 "behind an interface" boundary that keeps Mongo replaceable and lets
  tests run with **no cloud calls**.
- `app/Platform/Audit/MongoPlatformAuditLogStore.php` — the real `PlatformAuditLogStore`.
  Maps a `PlatformAuditEvent` to the B1-09 document shape and `insertOne`s it. Pins the
  collection to `platform_audit_logs` (constant `COLLECTION`) and **refuses** any other
  collection name in its constructor. Declares the required index set as the constant
  `INDEXES` and applies it via `ensureIndexes()`.
- `app/Platform/Audit/MongoDBPlatformAuditCollection.php` — production adapter wrapping a real
  `MongoDB\Collection` (duck-typed `insertOne`/`createIndex`). Constructed from config; **not**
  exercised by the test suite, so the repo needs no Mongo driver installed yet.
- `app/Platform/Audit/InMemoryPlatformAuditCollection.php` — test fake honouring the **same**
  contract (name, append-only insert, index declaration); records docs + requested indexes for
  assertions.
- `config/audit.php` — platform-audit wiring: driver (`fake` default / `mongodb` in prod),
  fixed collection name, and Mongo URI/database from env.
- `app/Providers/AppServiceProvider.php` (modified) — **binding swap** (see below).
- `tests/Feature/Platform/PlatformAuditStoreTest.php` — the B1-09 tests.

Reused unchanged from B1-04 (append-only interface shape preserved):
`PlatformAuditLogStore` (`record(PlatformAuditEvent $event): void`), `PlatformAuditEvent`,
`InMemoryPlatformAuditLogStore` (still used by B1-04's pure unit tests).

## Event document shape

Fields written to `platform_audit_logs` match the B1-09 contract exactly:
`timestamp, actor, action, target, target_tenant_id, category, request_id, result, reason,
access_session_context, ip, device` (+ `from`/`to` retained for `tenant_lifecycle` so a
transition is reconstructable). `category` is one of
`tenant_lifecycle | platform_config | security | billing | access`.

Transport/context fields (`target`, `request_id`, `result`, `access_session_context`, `ip`,
`device`, and an optional explicit `timestamp`) are read from the event's `context` array —
this is where the request-layer enriches a pure-domain event (e.g. B1-04 lifecycle events carry
only actor/from/to/reason; the platform endpoint in B2/B3 adds request_id/ip/device/session).
`timestamp` defaults to UTC "now" at write time when not supplied.

## Separate-collection guarantee (ADR-007 §7)

- Collection name is pinned in code: `MongoPlatformAuditLogStore::COLLECTION = 'platform_audit_logs'`.
- The store's constructor throws `InvalidArgumentException` if handed a collection whose
  `name()` is anything else (e.g. the tenant `audit_logs` sink from B1-11) — the two audit
  planes **cannot** be cross-wired, verified by
  `test_store_refuses_to_target_the_tenant_audit_collection`.
- `test_events_go_to_platform_audit_logs_not_tenant_audit_logs` asserts the target is the
  platform collection and explicitly not `audit_logs`.

## Append-only / immutable guarantee

- The `PlatformAuditLogStore` interface exposes only `record()`.
- The `PlatformAuditCollection` seam exposes only `insertOne` + `createIndex` — there is **no**
  update/replace/delete/drop/truncate method anywhere in the chain, so no code path can mutate
  or remove an event.
- `test_store_is_append_only_no_mutate_or_delete_methods` reflects over the interface, the Mongo
  store, and the collection seam and asserts none of a forbidden method set exists.
- `test_multiple_records_are_appended_not_overwritten` asserts repeated `record()` appends.

## Index set

Declared in `MongoPlatformAuditLogStore::INDEXES`, applied by `ensureIndexes()`:

- `{ category: 1, timestamp: -1 }`
- `{ actor: 1, timestamp: -1 }`
- `{ target_tenant_id: 1, timestamp: -1 }`

Each is a compound index whose first key is the primary filter dimension and whose second key is
`timestamp` descending (newest-first reads). Asserted by `test_the_three_required_indexes_are_declared`.
`ensureIndexes()` is idempotent and is intended to be run by a human against Atlas (steering rule 6 —
agents never `apply`).

## Real Mongo wiring vs the test fake

- **Production / local docker Mongo:** `config('audit.platform.driver') = 'mongodb'`.
  `AppServiceProvider` builds a `MongoDB\Client` from `MONGODB_URI` (Atlas, ap-south-1, via
  PrivateLink — ADR-003), selects `MONGODB_DATABASE`.`platform_audit_logs`, and wraps it in
  `MongoDBPlatformAuditCollection`. Requires the `mongodb` PHP extension + `mongodb/mongodb`
  package and real Atlas infra, both provisioned by a human (not committed; steering rule 4/6).
  Required env (kept out of the repo): `PLATFORM_AUDIT_DRIVER=mongodb`, `MONGODB_URI`,
  `MONGODB_DATABASE`.
- **Tests / default:** driver defaults to `fake` → `InMemoryPlatformAuditCollection` is bound,
  so **no cloud/Mongo calls** occur (steering). The real `MongoPlatformAuditLogStore` logic is
  fully exercised against the fake, which honours the identical contract.

## B1-04 binding swap

`AppServiceProvider::register()` previously bound
`PlatformAuditLogStore -> InMemoryPlatformAuditLogStore` (B1-04 placeholder). It now binds:

- `PlatformAuditCollection` → `mongodb` adapter or in-memory fake, per `config/audit.php`;
- `PlatformAuditLogStore` → `MongoPlatformAuditLogStore` wrapping that collection.

The lifecycle service (B1-04) is unchanged and now records through the Mongo store.
`test_lifecycle_transition_emits_an_event_via_this_store` drives a real `active → suspended`
transition through the container and asserts one `tenant_lifecycle` event lands in
`platform_audit_logs`. `test_container_binds_the_mongo_store_backed_by_fake_in_tests` asserts the
swap took effect (real store, fake collection, correct collection name) in the test env.
B1-04's pure unit tests still construct `InMemoryPlatformAuditLogStore` directly and remain green.

## Risks / follow-ups

- **Mongo driver not yet installed.** The production path (`driver=mongodb`) references
  `MongoDB\Client`; it will error at resolve time until `mongodb/mongodb` + the ext are installed
  and wired by devops/human. This is intentional (tests must not depend on the driver). B1-08
  (compose) brings up a local Mongo container; integrating the driver + a live-Mongo smoke test is
  a follow-up (devops/B1-08 + a later task), out of B1-09 scope.
- **No MongoDB migration mechanism in Laravel.** `ensureIndexes()` is the index-declaration seam;
  wiring it into a bootstrap/console command (run by a human against Atlas) is a small follow-up.
- **Field-level encryption:** platform audit fields here (actor id, tenant id, ip, device) are not
  salary/PAN/bank, so steering rule 4's field encryption does not apply to this collection; if
  future categories carry sensitive values, encrypt at the event-construction layer before
  `record()`. Flagged for the security reviewer (SEC-1).
- **Human gate:** no secrets committed; `MONGODB_URI`/credentials come from Secrets Manager/env.
  No ADR or `openapi.yaml` modified (verified: `git diff agent/B1-04 -- docs/adr openapi.yaml`
  is empty).
