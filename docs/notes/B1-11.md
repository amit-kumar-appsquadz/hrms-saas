# B1-11 — Tenant audit store foundation (`audit_logs`, Mongo behind an interface)

**Branch:** `agent/B1-11` (based on `agent/B1-06`)
**Depends on:** B1-06 (`TenantContext`, `BelongsToTenant`, `TenantScope`)
**Status:** implemented, tests green locally (72 passed / 145 assertions; 17 new).

## What changed

New tenant-plane audit sink under `backend/app/Tenancy/Audit/`, mirroring the
platform-side B1-09 structure so the two planes reconcile cleanly at merge:

| File | Role |
|------|------|
| `TenantAuditEvent.php` | Immutable value object for one tenant audit event. Carries NO `tenant_id` (the store stamps it from context). Resolves `occurred_at` (explicit or "now"). |
| `AuditLogStore.php` | Tenant audit seam: `record(TenantAuditEvent)` + `forTenant(): array`. Append-only (no mutate/delete). The sink B1-10 double-audit / B1-04 target later. |
| `AuditCollection.php` | Thin Mongo collection seam: `name()`, `insertOne()`, `createIndex()`, read-only `find()`. No update/replace/delete/drop — append-only at the type level. |
| `MongoAuditLogStore.php` | Real `AuditLogStore`. Pins collection to `audit_logs`; injects `TenantContext`; stamps/filters `tenant_id`; declares `{tenant_id, occurred_at}` index. |
| `MongoDBAuditCollection.php` | Production adapter over a real `MongoDB\Collection` (duck-typed). NOT exercised in tests. |
| `InMemoryAuditCollection.php` | Test fake honouring the same contract (append-only, tenant-filtered `find`, index capture). No Mongo/driver/network. |
| `config/audit.php` | Tenant audit config (`driver`, fixed `collection = audit_logs`, Mongo URI/db from env). **Tenant block only** — see merge note. |
| `app/Providers/TenancyServiceProvider.php` | Driver-selected binding: `fake` (tests) / `mongodb` (prod). |
| `tests/Feature/Tenancy/TenantAuditLogStoreTest.php` | 17 tests, the security evidence. |

Mirrors B1-09 (`PlatformAuditEvent` / `PlatformAuditLogStore` /
`PlatformAuditCollection` / `MongoPlatformAuditLogStore` /
`MongoDBPlatformAuditCollection` / `InMemoryPlatformAuditCollection`) but as a
parallel, separate set of `App\Tenancy\Audit\*` types. **No platform file was
read into or modified.**

## Guarantees

- **Separate collection (ADR-007 §7).** The store pins
  `MongoAuditLogStore::COLLECTION = 'audit_logs'` and its constructor **refuses
  any other collection name** (throws `InvalidArgumentException`), so tenant
  audit can never land in `platform_audit_logs` or vice versa — enforced in
  code, not just config. (Defensive, exactly as B1-09 does.)
- **Append-only / immutable.** Neither `AuditLogStore`/`MongoAuditLogStore` nor
  `AuditCollection` exposes any `update/replace/delete/drop/remove` method.
  Immutability holds at the type level — there is no code path that can mutate
  or remove an event. A test asserts the forbidden methods are absent.
- **Tenant scope (always present).** `tenant_id` is stamped by the store from
  `TenantContext::requireTenantId()`, never taken from the caller. The event VO
  deliberately has no `tenant_id` field — a caller cannot write for another
  tenant. Every persisted document has a `tenant_id`.
- **Cross-tenant isolation at the store.** `forTenant()` always filters by the
  currently resolved `tenant_id`, so a read for tenant A can never surface
  tenant B's events. This is enforced in the store itself (independent of any
  Eloquent global scope, since this sink is Mongo, not Eloquent).
- **Fail-closed with no tenant.** With no resolved tenant, BOTH `record()` and
  `forTenant()` throw `TenantResolutionException` (via `requireTenantId()`).
  Writes never produce a tenant-less document; reads never return all tenants'
  events ("no tenant = all" is forbidden).
- **Index.** `MongoAuditLogStore::INDEXES = [['tenant_id' => 1, 'occurred_at'
  => -1]]` — compound, **`tenant_id` first** (steering rule 2 / ADR-001 index
  strategy), `occurred_at` descending for newest-first reads. `ensureIndexes()`
  declares it idempotently (a human runs it against Atlas — steering rule 6).

## Real Mongo vs test fake

- `AuditCollection` is bound by driver in `TenancyServiceProvider`:
  - `fake` (default under `APP_ENV=testing`, and until the Mongo driver is
    installed) → `InMemoryAuditCollection`. **No cloud calls in tests**
    (steering). This is what the suite runs against.
  - `mongodb` (prod / local docker) → `MongoDBAuditCollection`, constructed from
    `config/audit.php` (`MONGODB_URI` / `MONGODB_DATABASE` from env; in prod from
    Secrets Manager via PrivateLink — ADR-003; never committed).
- `MongoAuditLogStore` is driver-agnostic: it depends only on the
  `AuditCollection` seam, so the exact same store code runs in tests and prod.
- The `MongoDB\Client` reference in the provider resolves lazily — only when the
  `mongodb` branch executes — so the file loads without the driver installed
  (same pattern as B1-09). `mongodb/mongodb` is NOT yet in `composer.json`; a
  human adds it + the PHP extension when wiring Atlas (steering rule 6).

## B1-09 merge-reconciliation note (`config/audit.php`)

This task is NOT based on B1-09, so my `config/audit.php` contains **only the
`tenant` block**. B1-09 introduces the SAME file with a top-level `platform`
block. At sprint integration the two copies must be reconciled into one
`config/audit.php` holding **both** `platform` and `tenant` blocks. The blocks
use disjoint keys and different fixed collection names, so the merge is
**additive — no key conflict expected**; keep both. (Also noted inline in the
file header.) The provider bindings are likewise independent: B1-09 binds the
platform store in `AppServiceProvider`; B1-11 binds the tenant store in
`TenancyServiceProvider`. No binding collision.

## Risks / follow-ups

- `MongoDBAuditCollection` is intentionally untested (no driver in CI). First
  real Atlas wiring should smoke-test `insertOne`/`find`/`createIndex` shapes
  by hand (document normalisation of BSON → array in `find()`).
- Field-level encryption of any sensitive payload (PAN/bank/salary) is NOT this
  task's concern — B1-11 is the transport/sink only. Callers must not pass
  plaintext sensitive fields through `context`; enforce at the emitting sites
  (B1-10 / later) per steering rule 4.
- `forTenant()` is a foundation read with no pagination/limit — fine for the
  seam, but the full tenant audit viewer (B5) must paginate (steering rule 3).
- Timestamp sort in the in-memory fake uses second-granularity (`strtotime`);
  acceptable for tests. Real ordering is Mongo's `occurred_at` sort.
