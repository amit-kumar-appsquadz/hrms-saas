# S0-04 — ADR-004 Async and queue design

What changed: Added `docs/adr/ADR-004-async-queue-design.md`. SQS one-queue-per-workload (imports, notifications, documents, punch-ingest, audit, payroll) each with a DLQ; Lambda for event glue; >~300ms work goes async; every message carries `tenant_id` so the global scope applies in workers; idempotent consumers for at-least-once delivery.

Risks: at-least-once + idempotency pushes complexity into consumers; DLQs need an alarmed redrive runbook (devops, Phase 2).

How to verify: read the ADR; confirm the queue list and the tenant-context-in-message rule. Open questions: FIFO needs and per-queue retry/backoff defaults.
