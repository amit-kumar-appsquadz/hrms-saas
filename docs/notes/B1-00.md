# B1-00 — Scaffold Laravel app + two-plane route skeletons

Sprint: B1 (Platform + Tenant Foundation), Wave 0 (serial blocker). Owning agent: Backend.

## What changed

Created the `backend/` Laravel application from scratch (there was no `backend/`
before this task) with the two-plane route skeleton wired but not implemented.

New / modified files (all under `backend/` unless noted):

- `backend/` — full Laravel application skeleton (composer-generated).
- `composer.json` — Laravel `^12.0`, `laravel/octane ^2.5` (steering: Octane),
  `phpunit ^11.0`. See "Framework version" below for why not `^11.0`.
- `bootstrap/app.php` — **authoritative** middleware + routing config (Laravel 12):
  - registers `routes/api.php` under prefix `api/v1` (tenant plane);
  - registers `routes/platform.php` under prefix `api/v1/platform` (platform plane);
  - defines two middleware groups `tenant` and `platform`, each containing only
    `DenyByDefault` (deny-by-default placeholder).
- `routes/api.php` — tenant plane. Open `GET /api/v1/health`; empty `tenant`-group block.
- `routes/platform.php` — platform plane. Open `GET /api/v1/platform/health`; empty
  `platform`-group block.
- `app/Http/Middleware/DenyByDefault.php` — placeholder guard returning `401` for any
  route behind a plane group. Replaced by real guards in B1-03 (platform) / B1-05+B1-07
  (tenant).
- `app/Http/Kernel.php` — **documentation/placeholder seam only** (see reconciliation).
- `tests/Feature/PlaneSkeletonTest.php` — smoke test (7 cases incl. the Unit example).
- `phpunit.xml` — enabled `DB_CONNECTION=sqlite` + `DB_DATABASE=:memory:` so tests make
  no MySQL/cloud calls (steering: no cloud calls in tests).
- `.env.example` — HRMS-stack placeholders (MySQL/Redis/SQS/S3, `ap-south-1`, base-domain
  pattern, no admin host). **`APP_KEY` empty; no secrets.** `.env` stays gitignored.

## Deny-by-default decision

Both plane middleware groups (`tenant`, `platform`) contain exactly one middleware,
`DenyByDefault`, which rejects every request with `401`. This satisfies the B1-00
security requirement and the Wave-0 "Guard-by-default" gate: no plane serves a request
unauthenticated until its real guard lands (B1-03 / B1-05 / B1-07).

The **only** intentionally-open routes are the two health checks, and they are
registered **outside** the plane groups on purpose. They read no tenant/platform
context and do no DB work, so they stay fast and cannot leak anything.

A dedicated test (`*_denies_by_default`) registers a throwaway route in each group and
asserts it is rejected `401`, so a future change that accidentally makes a plane fail
open will break the suite.

## Reconciliation (not an ADR/contract change)

- **`app/Http/Kernel.php` vs `bootstrap/app.php`.** The B1 plan names
  `backend/app/Http/Kernel.php` as the home of the two middleware groups. That reflects
  the pre-Laravel-11 skeleton. Laravel 12 (the only non-advisory-blocked stable line,
  see below) declares HTTP middleware in `bootstrap/app.php` via `->withMiddleware()`.
  I put the authoritative group definitions there and kept `app/Http/Kernel.php` as a
  documented placeholder that mirrors the group map for discoverability (and is covered
  by a test). This is an implementation-location detail, **not** an architecture change:
  the behavioural contract the plan requires — two distinct, deny-by-default plane groups
  plus two open health routes — is fully honoured. No ADR, no `openapi.yaml` touched.
- **Framework version.** `composer create-project laravel/laravel:^11.0` failed: Composer
  blocked every available `laravel/framework` 11.x patch (`v11.0.0 … v11.57.0`) under
  active security advisories (`PKSA-*`). Rather than ignore advisories or pin a vulnerable
  release, I moved to Laravel `^12.0` (installed `12.69.3`), which resolves with
  **"No security vulnerability advisories found."** Laravel 12 is the current stable line
  and keeps the Octane requirement. If the human prefers 11.x, that requires an advisory
  exception decision — flagged here, not self-resolved.

## No ADR / OpenAPI drift

- No ADR file or `openapi.yaml` was modified (only `docs/notes/B1-00.md` added).
- Route prefixes match the contract `servers` block: tenant plane `…/api/v1`, platform
  plane on the base domain `…/api/v1/platform/*` (ADR-007 plane separation).
- `/health` is an operational route and is **not** part of the API contract; it is the
  task's explicitly-sanctioned open route and adds no contract surface.

## Risks / notes for later tasks

- `DenyByDefault` is a hard 401 for everything in a plane group. Later tasks (B1-03,
  B1-05, B1-07) must **replace** it in the group, not merely prepend a guard, or routes
  will stay denied. The group names (`tenant`, `platform`) are the integration seam.
- `.env` was created by composer with a real local `APP_KEY` for dev; it is gitignored
  and not committed. Only `.env.example` (empty key, placeholders) is committed.
- **Ownership boundary:** no `docker-compose`, `docker/**`, or `.github/**` were created
  here — those belong to DevOps (B1-08). Local MySQL/Redis/MinIO therefore are not yet
  provisioned by this repo; tests avoid them via the sqlite-in-memory phpunit config.
- MongoDB audit stores are **not** in this task (behind an interface, B1-09/B1-11).

## How to verify

```powershell
# from repo root
cd backend

# dependencies (already installed; re-run if vendor/ is missing)
composer install

# app boots on Laravel 12
php artisan about --only=environment

# both plane health routes are registered, distinct, correct URIs
php artisan route:list --path=api
#  GET|HEAD  api/v1/health           -> tenant.health   (routes/api.php)
#  GET|HEAD  api/v1/platform/health  -> platform.health (routes/platform.php)

# smoke + deny-by-default tests (no MySQL/cloud; sqlite :memory:)
php artisan test
#  Tests: 7 passed (16 assertions)
```
